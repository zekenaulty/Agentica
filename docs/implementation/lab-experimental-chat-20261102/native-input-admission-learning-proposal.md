# Scoped learning — native token admission

Accepted correction for Agentica's development learning lane. This refines `lab-context-selection-uses-dispatch-envelope`; preserve its exact-request consistency lesson while superseding any use of its byte proxy as production model-token admission.

**Lesson.** Equal preflight and dispatch bytes prove a consistent request boundary. They do not establish token-window fit. When a host configures model-token budgets, use the provider's native count of the same model and semantic input, bound to the exact generation-request hash. Keep serialized characters, wire bytes, input tokens, output reservation and returned usage distinct.

**Decision rule.** Check current input and the declared recent floor before optional retrieval. If history or exact quotations must shrink, record complete-pair/range omissions; never silently rewrite current input, instructions, the floor or saved limits. Identify the failed dimension. A native-count failure must remain unavailable, not a proxy estimate. Count-only inspection performs disclosed provider HTTP work but creates no turn or generated response; cache/count attempts separately from generation.

**Evidence and boundary.** The complete Web suite passes 292 tests with one platform skip; the host/chat JavaScript suite passes 104. The measured compiler, native counter and real HTTP-host fixtures prove bounded selection, count-request mapping, stateless dispatch linkage and failure behavior against synthetic HTTP. In the actual browser, Check context measured the unchanged owner draft with four protected turns and optional recall at 28327 / 62976 input tokens, using saved settings revision 9, without creating a turn or generated response. See [qualification](qualification.md#native-token-admission-correction--3-november-2026). Earlier byte-proxy fixtures did not prove that outcome; this correction still makes no live generation/output or answer-quality claim.

**Recheck when:** the model, count endpoint/schema, request composition or admission policy changes. A successful input count alone does not qualify output limits, reasoning effort, tools or answer quality.
