# Native continuation across a governed run

`AgenticaRunner` gives an optional `IWorkflowPlannerSessionFactory` one session per run attempt. The runner disposes the session on success, failure, cancellation, or blocked completion; blocked retries create a new run identity and session. Both factory and returned session retain their external-planner security classification. A session cannot bypass the existing outbound data boundary policy.

`LlmWorkflowPlanner` implements that factory. Each session holds only its most recent private native continuation, bound to the host's run ID, objective, origin, authorization scope, provider, model, and system instruction. Requests from another run or objective are rejected before dispatch. Superseded carriers are disposed. Direct standalone planner calls retain their previous call-scoped behavior, while direct hosts can use `BeginSession` and attach the same `PlanningSessionContext` to their planning requests.

After a tool executes, the runner snapshots its normalized observation and receipt into the next planning request. The planner compiles the current objective, legal tool surface, execution constraints, and public evidence, then appends that fresh user input to the provider's private history. Existing JSON workflow proposals continue through the runner's schema, effect, authority, and host completion checks. Retained history does not grant tools and cannot replace current host policy.

Private history counts toward both the configured character ceiling and the model token allowance. If it does not fit, or its model/instruction binding changes, the session disposes it and dispatches the freshly compiled request without native history. The compilation receipt records the include/reset decision, full input character count and hash, and token estimate when configured. Provider state remains in memory and is excluded from normal request/response serialization and execution proof. String disposal releases references and does not guarantee erasure of runtime copies.

JSON repair recomputes the compilation receipt and matching metadata after selecting native replay or quoted fallback. The hash, character count, token estimate, and native-history decision describe that repair input. The `utf8-request-byte-proxy-v2` estimator excludes host-only request metadata, which none of the adapters transmits; it still counts the logical request and private native history with its existing conservative overhead. Excluding bookkeeping prevents the recorded estimate from contributing to its own token count. This remains a byte proxy, not a provider tokenizer.

The integration tests run the actual five modern adapter parsers with streamed HTTP fixtures. They prove a query produces a normalized observation/receipt, the next provider request carries both that evidence and native reasoning, a validated host action changes state exactly once, host completion cites the normalized receipt, and all carriers are disposed. Additional tests cover run/objective/authority isolation, changed carrier bindings, budget resets, cancellation, and external-session dispatch policy. These fixtures do not establish live account availability. Provider-native function calls and durable private-state persistence remain separate contracts.
